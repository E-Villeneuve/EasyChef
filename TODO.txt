Like/favorite actions are wired to the wrong backend behavior. The frontend sends POST and DELETE from ViewRecipe. Those routes use generic create/update/destroy views in recipes/views.py, while the serializers define custom update/delete methods in recipes/serializers.py. In the installed Django REST Framework, DELETE uses the default destroy behavior, which deletes the recipe itself—not just its like or favorite. Make these actions safe and track each user’s state.

Recipe creation doesn’t reliably save the recipe’s details. In CreateRecipe, ingredient submission loops over instructions, not ingredients. Instructions are initialized to placeholder steps (line 36), and image submission calls .map() on files even when no files were selected (line 100). It also appends an object URL instead of the file itself (line 104). Fix the submission flow and add error/success handling.

The recipe edit button leads to a missing page. It navigates to /edit-recipe/:id in ViewRecipe, but AnimatedRoutes has no matching route.

Rating is only a display control. Its change handler just logs the selected value in ViewRecipe; there’s no completed rating submission flow.
